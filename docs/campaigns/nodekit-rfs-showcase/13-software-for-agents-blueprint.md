Agents are still being forced to use software like humans: find a screen, click the right button, preserve brittle browser state, and hope the action worked.

YC's Software for Agents request asks what software should look like when agents are first-class users.

NodeKit's proposed wedge is an agent-native application substrate.

User: the builder and operator of an agent application.

Job: let an agent perform consequential work through typed, governed contracts.

Artifact: an approved product artifact plus a content-bound proof receipt.

The real point is shared state. The machine interface and human interface should operate on the same cases, proposals, approvals, versions, and receipts. The agent should not receive an ungoverned back door, and the human should not have to trust “the agent said it finished.”

This is Blueprint 13/16, not a deployed-product claim. The build will be judged on typed discovery, interruption recovery, approval boundaries, production verification, and exact cost accounting.

What proof would you require before trusting an agent to complete consequential work?
