# Validated sourcing receipt types

A developer consuming a sourcing draft needs the model name to remain text and token counters to remain numbers. The provider already checks those values at runtime, but JSON.parse allowed any to leak into the inferred action return. Two local annotations preserve the validated types.

The independent [source judgment](E4f_NODEBENCH_RETURN_LEAF_SOURCE_JUDGE.md.txt) approves the exact one-file patch: nine invalid contracts are rejected, all nine valid contracts remain accepted, and all four tested return leaves are concrete. The provider is read from its actual edited file. TypeScript emits byte-identical JavaScript before and after; no runtime logic, provider request, generated binding, dependency or configuration changes.

This proof uses the retained module-local API experiment in memory. The actual on-disk generated API and project-graph failures remain unresolved. It is not a whole-app typecheck or a complete repository grade. The existing 25-second timeout bounds provider I/O, not every surrounding audit mutation.

The [manifest](manifest.json) binds the raw baseline, candidate, compiler reports, actual diff and replay materials. The [portable replay guide](E4f_NODEBENCH_RETURN_LEAF_PORTABILITY.md.txt) distinguishes its argument/path checks from the earlier complete compiler runs. Use its documented commands with a fresh output directory and the reviewed base commit; never overwrite the historical results. Original machine paths in raw reports identify where those observations occurred; originalRef maps packet copies to those references.

Commit identity and shared checks follow normal repository review. No production deployment is claimed by this local proof.
