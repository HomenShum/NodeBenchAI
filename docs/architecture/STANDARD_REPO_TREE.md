production runtime. `.nodeagent/` is compiler output, not evidence that runtime
cutover has happened.

## Known conformance violations (declared, not hidden)

1. **Repo-local runtime** — this repo's harness predates NodeAgent and is a
   *migration source*, not a vendored copy (`forbidVendoredRuntime: false`).
   Flips after the ecosystem phase-2 extraction (NodeRoom runtime → NodeAgent)
   and this repo consumes `@nodeagent/runtime`.
2. **Hand-maintained global tool registry** (`toolRegistry.ts`) — standard
   rule 4; resolved by the generated-registry compiler, not by hand.
3. **Compiled/runtime split** — NodeKit resolves a canonical application
   definition, but `repo-local-nodebench` still executes production work. The
   compile hash proves the declared surface, not same-path production parity.
4. **modelCatalog duplication** — copies exist in NodeRoom and NodeAgent;
   resolved by `@nodeagent/providers` extraction.

## Brownfield conformance level

Current level: **L2 — mapped and compiled**.

- L1 registered: the repository contract validates against the platform catalog.
- L2 mapped: the application, provider, backend, capability pack, policies, and
  existing evaluation commands resolve into one secret-free config hash.
- L3 wrapped remains: the existing runtime must emit canonical NodeAgent events,
  traces, and ProofLoop receipts through an adapter.
- L4 shadowed remains: the canonical runtime must run frozen fixtures without
  writes and be compared with the existing production path.
- L5 hybrid through L7 enforced remain: promote one proven workflow at a time,
  retire the legacy route only after parity, then fail CI on new protocol forks.
